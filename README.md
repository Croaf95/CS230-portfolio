# CS-230: Operating Platforms Portfolio
## Software Design Document – The Gaming Room

This repository contains my completed **Software Design Document for The Gaming Room**, created for **CS-230: Operating Platforms** at Southern New Hampshire University. This artifact represents my work analyzing system requirements, evaluating operating platforms, and designing a scalable, multi-platform software solution based on client needs. It is included as a professional portfolio artifact demonstrating my approach to software design and system planning.

---

## Client and Software Requirements

The client for this project was **The Gaming Room**, a company seeking to expand its existing game, *Draw It or Lose It*, into a **web-based application** capable of running across multiple operating systems. The client required the system to support multiple teams and players while ensuring that **only one instance of the game exists in memory at any given time**. Additional requirements included scalability, security, reliability, and compatibility across major platforms such as Windows, macOS, Linux, and mobile environments.

---

## Strengths in Developing the Design Document

One area where I performed particularly well was translating the client’s business requirements into structured technical design decisions. I evaluated operating platforms and architectural constraints while applying object-oriented design principles such as controlled access and instance management. My documentation clearly connects user needs to system design choices, supporting both clarity and long-term maintainability.

---

## Value of the Design Process

Developing the software design document prior to implementation was extremely valuable. The design process required me to consider architectural challenges early, including concurrency and resource management. Planning these elements in advance helped streamline later development and reinforced the importance of structured design when creating software intended for multiple users and platforms.

---

## Areas for Improvement

If I were to revise one section of the document, I would expand the **platform evaluation and deployment analysis**. While the original evaluation met project requirements, providing deeper comparisons of cloud-based and local deployment options would improve scalability planning and real-world applicability.

---

## Interpreting and Implementing User Needs

I interpreted user needs by focusing on fairness, functionality, and accessibility. Design decisions such as enforcing unique game instances and supporting multiple teams were driven directly by gameplay requirements. Considering user needs during the design phase is essential to ensure the final product is intuitive, reliable, and aligned with user expectations.

---

## Software Design Approach and Future Application

My approach to software design emphasizes understanding requirements first, followed by structured planning and careful architectural evaluation. Throughout this project, I used design documentation, platform comparisons, and object-oriented principles to guide decision-making. In future projects, I will continue applying these strategies while placing increased emphasis on scalability and early requirement analysis.
